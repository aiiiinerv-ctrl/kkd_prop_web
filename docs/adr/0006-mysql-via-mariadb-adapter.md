# MySQL via the mariadb driver adapter, superseding ADR-0002 (SQLite)

The site runs on Prisma 7 + MySQL through the `@prisma/adapter-mariadb` driver adapter. This supersedes ADR-0002, which chose SQLite via `better-sqlite3` — that decision stood until the August 2026 cutover and its reasoning (no external database to provision, whole app in one container with the DB on disk) was sound for the assumptions it named. What changed is the hosting target, not the write volume: production moved to DirectAdmin/CloudLinux shared hosting, where the Node process can be restarted or relocated by the panel and a file-on-disk database is not a safe place for lead data, while a managed MySQL instance is included and backed up by the host. The migration also removed the "swap to a postgres:// URL later" escape hatch ADR-0002 kept open — the adapter model still makes another engine possible, but the schema and migrations are now MySQL-shaped (InnoDB index-length limits forced narrowing the `AuditLog` composite index, for one).

Two consequences worth knowing before touching the database. Local development needs the MySQL container running (`docker compose up -d mysql`) — there is no file to fall back to, so a missing container fails as a pool timeout during `next build`'s static generation rather than as an obvious connection error. And production has no external MySQL access: schema changes reach it only through the deploy pipeline, which is why `docs/plans/kkd-shared-hosting-redeploy-runbook.md` is required reading before a redeploy rather than optional background.
